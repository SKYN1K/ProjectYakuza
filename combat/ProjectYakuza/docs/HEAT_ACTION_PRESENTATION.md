# Heat Action presentation

HeatActionPresentation separates visual/audio presentation from authoritative damage and QTE evaluation. HeatRush starts it for the owner timed action and remote paired-animation jobs; matching cleanup stops it. Server damage messages no longer replay locally reconstructed sounds or effects. Observers use their own native animation phase, so network delivery delay does not queue a second set of impacts. The protocol is unchanged.

The controller reads AttackEffects.findTrack for the currently playing actor clip. It prepares an original GameSoundClip up to 160 ms before contact and subtracts that exact clip's measured strong-transient lead-in from the contact time. The existing GameSound user volume still applies, including the mod Sounds slider; primary/layer gains remain 0.55/0.30. It does not change Voices volume. Primary and optional layered sounds use world emitters. A presentation arriving over 100 ms late is dropped, independently of the longer gameplay/network contact grace period. No game clock, damage or QTE timing is changed.

HeatPresentationData contains code-side native victim head/neck/torso contact samples, transformed through AttackEffects.project with the actor's rendered animation angle and victim's current world root. HitEffects and BloodEffects copy the same world point for a one-shot burst. They no longer apply the generic standing/floor height to these samples. Original sprites, alpha and scale are retained. Ground trample explicitly samples the victim head. Weapon Heat Actions use body-impact sounds for bare-hand contacts rather than the weapon profile's generic impact sound. Rush uses punch/kick impacts instead of rising boost layers.

Custom Heat Actions retain their authored contacts, cue, layers, strong/charged and qteIndex fields. Without a generated clip entry they use existing root-relative effect placement and a 35 ms audio lead fallback. Optional presentation contact metadata consists of atMs, original contact index, cue, base, layers, feedback, native point and bone. base resolves body sounds from the registered style rather than its equipped weapon view. An empty layers array suppresses source contact layers. Do not change QTE or damage timestamps to compensate for sound latency.

The numeric data and provenance manifest are reproducible with tools/combat-tests/build_heat_presentation.py. Its default mode verifies; --write rebuilds the Lua numeric data and JSON manifest. It imports existing PZ clips with B42 Jassimp and samples the existing skeleton's forward kinematics. Audio analysis decodes PCM only in memory and writes no media. Source paths/hashes, selected bones and measured clip lead-ins are recorded in heat-presentation-data.json. The tool does not create or modify visual, audio, model or animation assets.

Render polling is active only during a session, capped at eight simultaneous actors. Pause freezes emission. Style changes, unequip, death, action interruption, backward animation restarts, save and main menu clear it. Missing tracks get 1.5 seconds from the last observed phase before cleanup. Natural completion preserves an impact sound's existing tail.
