# Project Yakuza 0.99.1 validation

This patch addresses action readiness, crowded-horde grab selection and bottle attack recovery. The available failure-session log reports v0.98.0, contains no Project Yakuza exception at the reported point, and does not identify an exact triggering action. The user could still attack and quickstep. Vanilla debug cursor toggles only change cursor visibility. Horde Manager spawning by itself does not establish a player action lock. The fixes target reproduced defects rather than claiming a live reproduction of that session.

The installed B42 IsoGameCharacter.hasTimedActions implementation returns true for either a nonempty native character-action stack or IsPerformingAnAction. Previously Quicksteps and HeatRush cleared that boolean only while PerformingAction still matched their owned clip. Resetting the selector first reproduces the residual readiness lock. The shared releaseActionAnimation helper releases its owned boolean even after the selector clears, provided the native stack is empty or contains exactly its own queued action. A foreign nonempty clip, replacement mod context or unrelated native action is preserved. Style entry uses the same scoped release while leaving native queue completion to ISBaseTimedAction. No general player-state reset or attack-flag bypass was introduced.

The quickstep fixture reproduces blank selector plus busy boolean through actual completion, tests repeated completion and foreign/replacement ownership, and models native hasTimedActions as stack-or-busy. The Heat Action suite clears the selector immediately before actual paired completion and verifies the busy boolean is released; it also checks failure-clip ownership and a foreign queued action. Style entry verifies the same blank-selector case while its own native action is still in the queue. The grab suite places eight attacking candidates ahead of a ninth eligible candidate. Grab targeting now retains the complete distance-sorted candidate set from the same bounded MultiHit scan, with all visibility, reach, floor, ownership and state checks intact.

Bottle followups previously released at approximately 65 percent of each source light animation. Their three chain markers now occur two original frames before the end: 38/40, 33/35 and 45/47. Light, heavy and ground selectors disable earlyTransitionOut. Native LiveAnimNode.onNonLoopedAnimFadeOut invokes end events and marks transition-out; disabling that track flag retains the complete single-swing source recovery instead of firing its end during the early fade. The native AnimNode parser confirms the new policy, while the weapon Kahlua suite consumes actual XML event timings and verifies no queued heavy handoff at 67 percent, successful late handoff, and no automatic cancellation of a lone swing. Deliberate light quickstep cancellation remains separate and unchanged.

Five owner bottle selectors and twenty event-free observers change. All 450 MP observer nodes retain matching clips, speed, blend settings and conditions. WeaponMotionProbe validates 171 native selector/isolation/blend cases. The five original bottle .x files import through the native JAssImp animation pipeline; their source and output hashes, all other supplied motions, models, textures and audio remain identical to v0.99.0. The reproducible weapon builder and selector provenance hashes are updated without rebuilding motion assets.

All 30 rebuilt Kahlua suites pass and all 83 production Lua files compile. Re-running the five affected suites against the prior cleanup/targeting code or old bottle markers fails at the new regression assertions, confirming those tests detect the original defects. Source-comment scanning reports zero comments and its six lexical tests pass. Installation checks the prior v0.99.0 archive byte-for-byte, backs up only existing files that change, copies the patch and verifies the complete final installed file set. Publishing uses a fresh v0.99.1 release/tag with the install ZIP; installed/source/archive bytes and remote tag revision are checked.

Gameplay timing, the user's exact debug/horde sequence and real multiplayer behavior still need assessment after restarting matching client/server versions. Project Zomboid was not launched during validation.
