# Project Yakuza Emotes 0.2.3 validation

EmoteReadinessProbe reproduces the installed B42 behavior directly on an offline native player fixture. With an empty action stack and no reading or action variable, isCurrentlyBusy becomes true for three chasing zombies or one very close zombie. Native hasTimedActions and isReading remain false. Actual native reading and action-stack guards are separately verified. Project Zomboid is not launched.

The addon replaces the broad busy check with native hasTimedActions and isReading checks, retaining the existing Lua action queue and optional Project Yakuza action guard. Its optional CVF adapter installs the same readiness predicate through CustomVoice.canPlayEmote. Immediate binding and an OnGameStart hook cover both provider load orders; repeated binding is idempotent. No CVF or voice-pack source or installed file is edited. Existing native CVF dispatch, IDs, equipment policy and wheel hooks remain in place.

Kahlua verifies 209 addon assertions, 27 actual native-menu assertions without CVF and 32 assertions for each actual native/pinned-CVF provider order. Cases include successful playback beside zombies, active native and Lua actions, reading, optional combat actions, original movement/aiming and unsafe-state rejections, all weapon and unarmed emotes, unknown CVF IDs, replay protection, late provider binding and unchanged vanilla delegation. Both production Lua modules compile.

All 50 addon animation/selector files remain byte-identical to 0.2.2, including the corrected Majima greeting, Step Up movement and all spear calibrations. No motion, texture, model or sound conversion occurs, so new importer/pixel conversion checks are not applicable. Existing source/output provenance and standalone-isolation validation pass. Combat source and installation remain byte-identical to 0.108.0; installed CVF and the separate voice pack remain unchanged.

Source-comment scanning and all six lexical tests run before publication. Installation verifies the complete installed 0.2.2 release baseline, backs up changed existing files only, copies changed/new files and checks the final complete source/installed inventory. The separate release ZIP and its uploaded digest/tag commit are verified. Live gameplay, movement blending and multiplayer remain untested.
